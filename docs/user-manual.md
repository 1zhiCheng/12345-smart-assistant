# 芜湖政务 Agent（12345 智慧助手）使用手册

适用对象：演示人员、12345 热线营业员、承办部门管理员、系统管理员、录音标注人员和部署运维人员。

本系统是**工单智能辅助系统**，不是自动办结系统。模型可以转写、抽取、分类、检索政策并起草回复；
工单确认、转派与办结始终由有权限的工作人员完成。

## 1. 先认识系统

### 1.1 从群众诉求到办结的流程

```text
群众来电/文本
  → 营业员录入、核对转写、生成并确认工单
  → 待领取（pending）
  → 部门管理员领取（processing）
  → 分类、承办部门、政策依据和回复草稿人工审核
  → 确认回写办结结果（completed）
```

发现多件事项时，营业员可先生成多张子工单草稿；每一张都需要单独确认，不能自动转派。

### 1.2 用户和权限

| 身份 | 系统角色 | 可做什么 | 不能做什么 |
| --- | --- | --- | --- |
| 群众 | 无登录账号 | 通过电话或线下渠道反映诉求 | 不直接登录本系统 |
| 热线营业员 | `operator` | 文本/录音录入、人工校对、补充追问、拆单、确认工单 | 不能领取或办结承办部门工单；不能管理知识库 |
| 部门管理员 | `department_admin` | 查看本部门队列、领取工单、审核分类和回复、管理本部门文档和审核单 | 不能访问其他部门数据；不能改变全局策略 |
| 系统管理员 | `system_admin` | 全局工单处置、部门与知识资产、审核态势、全局 Loop、记忆与 Agent 网络 | 不能绕过工单人工审核；当前界面不能直接新建管理员账号 |
| 录音标注人员 | 离线工具，不使用业务登录 | 听审冻结录音、修正转写/角色/时间戳、导出私有标注 JSON | 不能把真实录音或私有标注上传到公开服务/Git |
| 运维人员 | 服务器/容器权限 | 配置密钥、模型、数据库、备份、部署与监控 | 不应借此查看或传播不必要的群众原始数据 |

## 2. 启动和进入系统

### 2.0 双击启动（工作人员推荐）

在项目根目录双击 [启动芜湖政务助手.cmd](../启动芜湖政务助手.cmd)。启动器会自动启动本机后端和前端、
等待服务就绪并打开工作台。关闭“芜湖 12345 智慧助手”窗口，或点击“关闭系统并退出”，它只会结束
自己创建的服务进程；不会关闭占用端口的其他程序。

启动器会以最小化方式运行后台控制进程，并单独弹出控制窗口。如果启动失败，窗口会显示原因，并把详细信息写入
`logs/desktop-launcher/launcher.err.log`。

启动器运行的是前端已构建的 standalone 服务，并会自动同步页面静态资源；如果后端认证初始化在 8 秒内没有返回，
页面会降级显示登录页，不会无限停留在“加载中”。

首次使用仍需具备 Python 虚拟环境、前端依赖和 Node.js 22。若缺少依赖，启动器会给出明确提示；
完成一次依赖安装后，日常使用不再需要打开终端。启动日志位于 `logs/desktop-launcher/`。

### 2.1 本机演示版（当前常用）

在两个 PowerShell 窗口中执行。该模式使用内存数据库与测试向量，仅适合页面演示和功能调试，
关闭服务后业务数据会丢失。

**窗口 A：后端**

```powershell
cd 'C:\Users\10415\Desktop\芜湖政务Agent'
$env:STORAGE_MODE='memory'
$env:EMBEDDING_PROVIDER='hash'
$env:VECTOR_BACKEND='memory'
$env:PI_AGENT_ENABLED='false'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

**窗口 B：前端**

```powershell
cd 'C:\Users\10415\Desktop\芜湖政务Agent\web'
$env:BACKEND_URL='http://127.0.0.1:8000'
npm run dev -- -p 3000
```

浏览器打开 <http://127.0.0.1:3000>。若页面显示“无法访问此站点”，先检查两个窗口是否仍在运行；
若端口被占用，换一个前端端口并使用新地址。

### 2.2 Docker 完整版（演示、联调或部署推荐）

在项目根目录复制环境变量模板为 `.env`，**先替换所有示例口令和 `AUTH_SECRET`**，并设置首个系统管理员：

```env
BOOTSTRAP_ADMIN_USERNAME=competition_admin
BOOTSTRAP_ADMIN_PASSWORD=请设置至少12位的强密码
BOOTSTRAP_ADMIN_NAME=系统管理员
```

Docker 生产同构配置会从 `models/bge-small-zh-v1.5/` 加载本地中文向量模型；该目录缺失时后端会
按安全策略停止就绪，不能把 hash 测试向量当作正式知识库。语音转写如需离线运行，还应准备
`models/faster-whisper-turbo/` 和 `models/speaker-diarization/campplus.onnx`。

再执行：

```powershell
cd 'C:\Users\10415\Desktop\芜湖政务Agent'
docker compose up --build -d
docker compose exec backend python -m scripts.seed_data
docker compose exec backend python -m scripts.ingest_department_files --base /app/wuhu_knowledge_base --skip-conflicts --skip-metadata-llm
docker compose ps
```

完整版本前端地址为 <http://127.0.0.1:8080>，后端接口文档为 <http://127.0.0.1:8000/docs>。
首次管理员可登录后，应从 `.env` 或部署 Secret 移除 `BOOTSTRAP_ADMIN_PASSWORD`，并保存好正式账号。

### 2.3 登录、注册和演示账号

登录页的“注册营业员”只能创建 `operator`，注册成功后会直接进入受理工作台。这一限制用于避免任意用户把自己注册为管理员。

本机开发模式通常会创建下列**仅用于演示**的账号；Docker 生产模板默认关闭它们：

| 身份 | 账号 | 密码 |
| --- | --- | --- |
| 营业员 | `operator` | `operator123` |
| 城市管理局部门管理员 | `cgj_admin` | `admin123` |
| 系统管理员 | `admin` | `admin123` |

若上述账号提示密码错误，说明当前环境没有启用演示账号。请使用部署时配置的
`BOOTSTRAP_ADMIN_USERNAME` / `BOOTSTRAP_ADMIN_PASSWORD` 登录，或在**仅限本地演示**的环境中启用
`SEED_DEMO_USERS=true` 后重启后端。生产环境必须保持 `SEED_DEMO_USERS=false`，不得使用示例口令。

> 当前版本没有“管理员在页面中新建管理员”的功能。部门管理员需由受控部署/数据初始化流程创建并绑定
> `dept_id`；不要通过公开注册接口创建管理员。如需把此能力做成系统管理员功能，应另行增加审批、审计与密码重置流程。

## 3. 营业员使用指南

登录营业员账号后，进入“12345 热线智能受理工作台”。一次完整受理按以下步骤进行。

1. 选择“文本输入”或“录音输入”。文本应尽量包含时间、地点、经过和群众希望的处理方式。
2. 如果选择录音，上传已获授权且已按数据规范处理的 MP3、M4A、WAV、WEBM、OGG 或 MP4 文件。
   系统会转写并尽量标出“接线员：”“群众：”；可在上传区域直接播放原音频。
3. 校对角色化转写。低置信度声纹分离、未识别双人话轮或转写错误时，以原始录音为准直接修改文本。
4. 点击“分析诉求并生成工单”。系统会展示标题、时间、地点、事件经过、群众诉求、工单正文、完整度/忠实度提示与缺失项。
5. 修改不准确的字段；若系统提示缺少信息或含义不明确，填写追问补充区后重新生成。
6. 若页面提示多个事项，勾选需要拆开的事项，生成子工单草稿并分别核对。
7. 点击“人工确认工单”。确认后工单进入处置队列，状态为“待领取”。

### 录音转写的两种方式

- **本地模型**：设置 `ASR_PROVIDER=faster_whisper`，并配置本地 faster-whisper turbo 与 CAM++ 模型路径。
  原始录音留在本机，适合比赛录音和敏感数据。
- **兼容 API**：设置 `ASR_PROVIDER=openai_compatible`、`ASR_API_KEY`、`ASR_BASE_URL` 与 `ASR_MODEL`。
  使用前必须确认数据授权和脱敏边界。

当 ASR 不可用或模型文件缺失时，营业员仍可直接手动输入或修改文本，再继续生成工单；这属于设计好的降级路径。

## 4. 部门管理员使用指南

部门管理员登录后进入“部门治理空间”。系统按 `dept_id` 强制隔离数据，只能访问本部门范围内的工单、
文档、审核单、反馈和策略资产。

### 4.1 处置一张已确认工单

1. 在左侧打开“工单处置”，默认查看“待领取”。
2. 选择工单，核对群众诉求、时间、地点和事件经过；点击“领取工单”，状态变为“处理中”。
3. 点击“智能分类并检索政策”。系统给出事项类别、承办部门建议、官方文档切片引用和回复草稿。
4. 核对分类和承办部门，阅读每一条政策依据。证据不充分时，不应把模型推测写成政策结论。
5. 修改回复草稿。自动合规检查即使通过，也不等于可直接发送；仍需人工检查事实、时限、主体和措辞。
6. 只有分类、承办部门和审核后的回复都完整时，点击“确认分类、转派并办结”。系统回写处置结果。

### 4.2 维护本部门知识库

1. 打开“知识资产”，选择本部门。
2. 上传已确认来源的 PDF、DOCX、Markdown、TXT 或 HTML 政务文件。
3. 系统依次执行解析、清洗、切分、元数据、向量化、索引和关系发现；上传后会生成审核单。
4. 进入“可信审核”，逐题核对系统从新文档生成的问答和引用，提交审核结论。
5. 对错误内容进行更正、补充官方来源或下架文档；不要把采购公告、培训通知、无正文机构页等无关材料当作政策依据入库。

## 5. 系统管理员使用指南

系统管理员拥有全局视图，但不能绕过业务审核。各栏目用途如下。

| 栏目 | 用途 | 正确操作方式 |
| --- | --- | --- |
| 态势总览 | 查看部门、文档、审核量、反馈和 Loop 阶段 | 先判断数据是否完整，再决定是否调整策略 |
| 工单处置 | 处理跨部门或全局范围的已确认工单 | 同部门管理员流程，必须审引用与回复后办结 |
| 知识资产 | 新建部门、查看全局文档与切片 | 新部门必须指定稳定的 `dept_id`，官方文件需有来源和适用范围 |
| 可信审核 | 查看待审题目、正确率与“人逐步退出”条件 | 未达到最小样本量与正确率门槛前，保留人工审核 |
| 进化 Loop | 观察、反思、生成候选策略、灰度与部署 | 只在反馈与审核证据充分时运行；不要用真实冻结测试集反复调参 |
| 记忆与实验 | 查看事实平面、记忆平面、实验和反馈信号 | 不将用户隐私写入组织知识；检查来源失效与候选记忆 |
| Agent 网络 | 查看部门 Agent、文档量、Skills/Hooks/Rules 与副本 | 用于容量与健康观察，不代表模型可以自行发布政策 |

### “人在环中 / 环上 / 环外”是什么意思

- **人在环中**：每次关键判断必须人工审核，适用于新部门、新文档或低样本阶段。
- **人在环上**：系统可给出建议和低风险自动化，但人持续抽检和随时干预。
- **人在环外**：只有在达到最小样本数、正确率等门槛后，部分低风险流程可自动通过；工单办结与政策回复仍应遵循组织审批要求。

系统管理员设置全局 Loop 阶段，并不会让未达标部门自动跳过审核；部门的退出进度由各自累计审核数据决定。

## 6. 录音标注与冻结集评测（可选）

这不是营业员日常受理页面，而是比赛真实录音的私有质量评测工具。启动静态服务：

```powershell
cd 'C:\Users\10415\Desktop\芜湖政务Agent'
.\.venv\Scripts\python.exe -m http.server 8765 --bind 127.0.0.1 --directory backend\scripts
```

打开 <http://127.0.0.1:8765/audio_annotation_workbench.html> 后：

1. 载入 `local_evaluation/audio_annotations.official.prefilled.private.json`。
2. 选择比赛录音根文件夹，页面会按 `audio_ref` 匹配当前录音。
3. 使用变速播放和“播放”时间片逐段核对转写、角色、起止秒与语义字段。
4. 填写标注人，点击“批准并下一条”。真实冻结录音若缺时间戳、含 `unknown` 角色或缺任一通话角色，会被硬性拦截，不能批准。
5. 校验全部后导出 JSON；录音不会被写入 JSON。

真实录音、逐字稿、联系方式和私有标注不得上传公开平台、提交到 Git 或发送给未获授权的模型服务。完整说明见
[录音人工标注与语义评测指南](competition/audio-annotation-guide.md)。

## 7. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| `127.0.0.1:3000` 无法访问 | 检查后端 8000 与前端 3000 是否都在运行；检查端口占用；重新启动前端 |
| 登录提示密码错误 | 区分演示账号与正式账号；Docker 默认不创建演示账号；确认没有把环境变量中的账号/密码写错 |
| 可以注册但进入不了管理员页 | 注册入口只能创建营业员，这是正常的权限控制 |
| 上传录音后没有自动转写 | 检查 `ASR_PROVIDER`、模型目录或 API 配置；仍可手动修正/补录文本 |
| “本地语音模型不存在” | 核对 `ASR_LOCAL_MODEL_PATH` 是否指向实际 turbo 模型目录；模型不应放入公开 Git |
| 工单生成显示“规则降级” | 大模型未启用、超时、输出不合规或证据不足时会降级；先核对输入和模型配置，再人工编辑工单 |
| 管理员看不到其他部门数据 | 部门管理员按 `dept_id` 隔离，这是正常行为；跨部门事项由系统管理员处理 |
| 回复草稿有内容但无法办结 | 必须先领取，并补齐分类、承办部门和人工审核后的回复；若合规门禁提示风险，应先修改回复 |
| 标注工作台没有音频 | 先载入 JSON，再选择比赛录音根文件夹；若仍匹配不到，用“选择当前音频”单条兜底 |

## 8. 运行与数据安全检查清单

- 生产环境使用 MongoDB、Redis 和本地 BGE 向量；不要把 `memory` / `hash` 测试模式当作正式部署。
- `.env`、数据库口令、Token 密钥、真实录音、未脱敏工单、模型大文件和 `local_evaluation/` 均不得提交 Git。
- 启用外部 LLM 或云端 ASR 前，确认数据授权；默认 `INTAKE_LLM_ENABLED=false`。
- 每次上线前访问 `/readyz`，并运行后端测试与前端构建。
- 定期备份 MongoDB、上传文件、环境配置和知识库来源清单；恢复时先在隔离环境验证。

深入部署、接口和比赛实现细节分别见 [部署说明](deployment.md)、[接口说明](api.md)、
[比赛路线图](competition/roadmap.md) 和 [源码交付说明](../DELIVERY.md)。
