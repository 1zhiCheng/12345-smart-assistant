# 简历项目：芜湖 12345 智慧政务 Agent

> 角色请按真实情况填写为“核心开发 / 成员 A / 项目负责人”，不要虚构政务部门合作单位或上线经历。

## 完整简历版本（Agent / 后端 / 平台工程方向推荐）

**芜湖 12345 智慧政务 Agent｜面向热线受理的可信 RAG 与人机协同工单系统**　2026.XX - 2026.XX

**项目背景：** 原系统仅具备“文档切块 + 向量检索 + 单轮生成”的行政问答能力，无法处理真实 12345 录音的口语噪声、诉求缺字段、多部门协同、政策答复溯源与人工审批。负责将其重构为以业务状态机为主线、以可信 RAG 为事实底座、以 Agent Harness 为推理治理层的政务工单系统。

**解决方案：**

- **Agent Harness 与固定 DAG 编排：** 将概率性模型能力封装为 `ASR/角色识别 → Intent → Rewrite → Retrieval → Answer → Verify → Workorder/Handoff` 固定链路；FastAPI 治理层负责鉴权、部门范围过滤、状态机、超时降级、Trace 回放和人工节点控制，模型只承担语义理解、结构化整理和回复草拟，避免自由规划跳过检索或绕过审批。
- **语音受理与可信工单生成：** 使用 faster-whisper 在本地完成录音转写，引入说话人角色化、芜湖地名规范化、敏感信息脱敏与录音回放；将脱敏文本交由 LLM 按“事实—诉求—缺失信息”结构化，再以字段证据覆盖率校验模型输出。模型不可用、JSON 不合格或证据不足时自动切回规则引擎，并保留人工补录、校对、追问和多事项拆单。
- **可信 RAG 事实平面：** 以 MongoDB 管理文档来源、部门、版本、生效状态、Chunk 元数据与答案 Trace；收集 12 类、264 份芜湖官方正文，语义切分为 1,884 个可追溯 Chunk。检索采用 `BM25 + BGE-small-zh-v1.5 向量召回 + RRF 融合`，回答必须回填原始官方片段并携带来源，防止模型将会话记忆或历史工单误作政策依据。
- **语义路由与多角色协同：** 构建“高区分度事项规则 + 官方正文 BGE 多原型 + 关键词加权”的 12 类部门路由器；实现营业员、部门管理员、系统管理员三层 RBAC 和部门数据隔离。营业员确认工单后自动生成 Top-K 承办建议并进入对应部门处置队列，部门侧完成政策检索、回复修改、合规审核和办结回写；市民端支持自助问答，无法可靠解决时转营业员审核。
- **回复合规与人在环：** 针对政务回复实现来源引用、数字事实、个人信息、越权承诺、绝对时限和自动发布六类校验；所有 LLM 回复均为“待审核草稿”，只能经部门人工审核后办结。通过脱敏、最小权限、角色隔离和禁止自动发送，明确系统的安全边界。
- **Memory 与反馈自进化：** 迁移并实现会话记忆、组织知识记忆与程序性策略记忆的数据模型和上下文裁剪；接入显式反馈、追问、转人工、Verifier 结果与失败 Trace，按检索/意图/生成/知识缺失归因，生成 Skill、Hook、Rule 候选，并以回放、灰度实验和回滚机制约束策略生效。
- **异步任务与生产同构：** 实现文档入库、向量化、审核与 Loop 作业的 `queued/running/completed/failed` 状态模型、Worker 心跳、健康检查和指标接口；完成 MongoDB、Redis Stream、真实 BGE 向量、Docker Compose、Kubernetes/Helm、Prometheus 的集成与本地压测验证。桌面端通过 BGE 向量缓存实现双击启动后的快速语义检索，生产模式通过 `/readyz` 对 MongoDB、Redis、Worker 与真实向量执行就绪门禁。

**项目成果：**

- 在冻结官方文档留出集（12 类、24 条）上，语义路由 Top-1 / Top-K 达 **95.83% / 95.83%**；官方文档 RAG 达到 **Recall@5 100%、MRR 0.875、引用正确率 100%、答案关键点一致性 95.45%**。
- 完成 18 条、112.42 分钟比赛提供脱敏真实录音端到端基线：ASR 成功率 **100%**、双角色检出率 **94.44%**；针对字段抽取仍存在的口语噪声问题，落地“本地预标注 + 人工复核”工作台及 LLM/规则双路降级，而非将不可靠输出直接入单。
- 建立 11 条离线对抗用例与 3 条模型烟测的回复合规门禁，当前测试用例均通过且仍强制保留人工终审；后端自动化测试 **149 项通过**。上述指标均为本项目离线验证结果，不等同于真实政务生产效果。

**技术栈：** Harness Engineering、Agent DAG、可信 RAG、Memory Engineering、Loop Engineering、Skill Workflow、FastAPI、Python、Next.js、React、TypeScript、faster-whisper、DeepSeek、BM25、BGE-small-zh-v1.5、RRF、MongoDB、Redis Stream、Docker、Kubernetes、Helm、Prometheus、Pytest。

## 使用边界

- “真实录音 ASR 成功率 100%”仅来自 18 条比赛提供的脱敏录音，不建议在简历中单独夸大为生产效果。
- 真实录音端到端字段通过率仍低，系统因此保留录音试听、人工校对、补录和人工终审；这是可信政务系统的设计边界，而不是应被隐去的能力缺口。
- Docker、Kubernetes、MongoDB 和 Redis 的部署/集成能力可在技术栈中出现；如未实际部署到真实集群，面试中应准确表述为“完成部署配置与本地/压测验证”，不能表述为“已在线上政务系统稳定运行”。
