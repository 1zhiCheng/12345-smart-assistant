# 芜湖 12345 智慧助手比赛方案

## 一、项目定位

芜湖 12345 智慧助手面向热线营业员、部门管理员和系统管理员，辅助完成群众诉求的受理、
标准工单生成、事项分类、承办部门推荐、政策依据检索和回复草拟。系统不替代工作人员作出
最终行政判断，所有关键结果都进入人工确认节点。

## 二、业务问题

热线录音口语化、信息分散，营业员需要边听边记录；同一诉求可能跨部门，转派质量依赖经验；
回复还必须引用有效政策并避免越权承诺。项目把这些步骤连接为一条可审计流程，同时保留人工校对、
转派复核和回复终审。

## 三、完整流程

1. 营业员录入文本或上传脱敏录音。本地 ASR 输出带时间戳转写，CAM++ 辅助区分群众和接线员。
2. 系统先脱敏，再由大模型提取结构化要素并绑定原文证据。服务不可用或输出异常时使用规则基线。
3. 缺少具体地点、事件时间或诉求目标时，系统生成追问；营业员补充后重新形成草稿。
4. 营业员核对标题、摘要、正文和关键字段，确认后将工单送入处置队列。
5. 部门管理员领取工单。系统给出事项分类、主办部门、候选协办部门、推荐理由和风险提示。
6. 系统从 12 类芜湖官方知识库执行关键词与语义混合检索，生成带来源的回复草稿和回访口径。
7. 回复门禁检查引用、数字、隐私、越权承诺和完整性。部门管理员修改并确认后提交处理结果。

## 四、系统架构

- 前端：Next.js 15 与 React 19，提供三角色工作台。
- 控制平面：FastAPI 固定业务 DAG、鉴权、状态机、部门隔离、人工审核和合规门禁。
- 智能体执行：可选 pi-agent 负责受控模型调用；外部模型默认关闭。
- 数据平面：MongoDB 保存工单、文档、chunk、向量和审计信息；Redis Stream 承载异步任务、
  失败重试、死信和 worker 心跳。
- 本地模型：faster-whisper turbo、CAM++、BAAI/bge-small-zh-v1.5。
- 生成模型：兼容 DeepSeek/OpenAI 风格接口，只处理脱敏后的整理文本；规则方法提供确定性降级。

## 五、知识库与 RAG

知识库包含 12 个事项类别、264 份芜湖官方正文文档，各类 20 至 25 份。文档按标题、条款、段落
和语义边界切分为 1,884 个 chunk，保存来源单位、公开 URL、发布日期、类别、文档版本和 hash。
检索阶段融合 BM25 与本地 BGE 512 维向量，并在回复前核验引用 chunk 仍处于 active 状态。

当前离线评测为 Recall@5 100%、MRR 0.875、引用正确率 100%、答案关键点一致性 95.45%。
这些结果只代表现有官方测试问题；新增政策后应重新冻结测试集。

## 六、可信边界

- 工单草稿、部门推荐和回复草稿都不会自动对外发送。
- 原始录音与原始转写只在本地 ASR 链路处理；外部大模型仅接收脱敏后的整理文本。
- 模型失败时明确显示“规则降级”，不把降级结果伪装成模型输出。
- 每个抽取字段保留原文证据；每条政策依据保留官方来源 URL 与 chunk ID。
- 回复发布门禁覆盖无依据数字、隐私泄露、绝对承诺、引用失效和必要信息缺失。

| 评测对象 | 结果 | 结论 |

| 生产同构栈 | 264 文档零失败入库；检索与 100 个 worker 作业零错误 | Mongo、Redis、BGE、Worker 联调通过 |

## 八、现场演示

演示使用两个不同事项类型：城市管理夜间占道噪声，以及市场监管消费退款争议。第一个案例展示
录音、角色转写、缺失地点追问和主办部门推荐；第二个案例展示 12315 职责依据、候选协办部门、
回复门禁和人工修改。详细口播见 `demo-script-5min.md`。

## 九、落地路线

第一步在授权的脱敏录音上补充人工逐字稿与说话人时间戳，建立可计算 CER/DER 的独立留出集；
第二步在目标部署环境进行带 ASR 和模型调用的全链路容量测试；第三步接入工单平台前先完成数据
出境、模型服务、日志保留和账号权限评审，再从只读辅助和人工确认模式开始试点。

## 十、第三方模型与工具披露

| 组件 | 用途 | 数据边界 |
| --- | --- | --- |
| faster-whisper turbo | 本地录音转写 | 原始录音不外发 |
| CAM++ | 本地说话人聚类 | 声纹只用于当前录音分段 |
| BAAI/bge-small-zh-v1.5 | 本地语义向量 | 官方公开文档本地向量化 |
| DeepSeek/OpenAI 兼容接口 | 脱敏文本结构化与回复草拟 | 默认关闭，授权后启用 |
| MongoDB / Redis | 持久化与异步作业 | 部署在受控环境 |
| Next.js / FastAPI | 前端与业务 API | 不参与模型训练 |
